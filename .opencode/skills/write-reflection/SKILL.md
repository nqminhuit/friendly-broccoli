1. Use `../../../reflections/README.md`: `Format` and `Spoilers and visuals` for authoring/review; `Pipeline` only for builds/publishing. Read sections only if missing from context or changed.
2. Confirm work, author, part, filename and spoiler scope; ask about missing/unclear requirements, how many sessions. Check `../../../reflections/` for generated-name collisions. If you're not certain about the story arc, ask for clarification or do some web research to get more context, don't presume or guess.
3. Write as a warm, conversational literary critic for general viewers: themes, characters, writing style, simple vocabulary, natural spoken paragraphs. Use opening, thematic sections and closing; stay under 15 minutes including pauses but must be 10 minutes minimum. Include relevant anecdotes without inventing user experiences. Don't copy the same anecdotes or examples or content from other reflections, each reflection should be unique experience for the audience.
4. Apply the README template; write SEO metadata and specific, consistent image prompts with the full chosen style in each. Include the opening spoken warning when spoilers are needed.
5. Check metadata, duration, spoiler scope/warning, formatting, first image, prompts/style/thumbnail consistency, filenames, placeholders, secrets and image availability. Report unverified images rather than claiming build readiness.
6. Work on the main branch. Preserve existing voices/settings. Do not commit, push, dispatch or publish.
7. Review and revise the reflection for clarity, flow, and engagement. Ensure that the reflection follows the story arc, maintains a warm and conversational tone.
